In the previous posts, I covered the basics of Go concurrency and how to use channels and goroutines to write concurrent programs. This post covers advanced synchronization tools, error handling techniques, and common design patterns for concurrent Go applications.

## Advanced synchronization tools

### WaitGroup

The <Snippet>sync.WaitGroup</Snippet> type lets you wait for a collection of goroutines to complete. Use it when a group of goroutines has to finish before your program moves to the next step.

Here&apos;s an example of how to use <Snippet>sync.WaitGroup</Snippet>:

```go

package main

import (
    "fmt"
    "sync"
)


func main() {
    var wg sync.WaitGroup

    for i := 0; i < 5; i++ {
        wg.Add(1)
        go func(i int) {
            defer wg.Done()
            fmt.Println("Hello from goroutine", i)
        }(i)
    }

    wg.Wait()
    fmt.Println("All goroutines have finished")
}
```

The example creates a <Snippet>sync.WaitGroup</Snippet> and calls its <Snippet>Add</Snippet> method for each goroutine it needs to wait for. Then it calls <Snippet>Wait</Snippet> to block until all the goroutines have called <Snippet>Done</Snippet>.

### Mutex

The <Snippet>sync.Mutex</Snippet> type is a mutual exclusion lock that protects shared resources from concurrent access. Use it when only one goroutine should access a resource at a time.

Here&apos;s an example of how to use <Snippet>sync.Mutex</Snippet>:

```go
package main

import (
    "fmt"
    "sync"
)

type Counter struct {
    mu sync.Mutex
    value int
}

func (c *Counter) Increment() {
    c.mu.Lock()
    defer c.mu.Unlock()
    c.value++
}

func (c *Counter) Value() int {
    c.mu.Lock()
    defer c.mu.Unlock()
    return c.value
}

func main() {
    var wg sync.WaitGroup
    counter := Counter{}

    for i := 0; i < 1000; i++ {
        wg.Add(1)
        go func() {
            defer wg.Done()
            counter.Increment()
        }()
    }

    wg.Wait()
    fmt.Println("Counter value:", counter.Value())
}
```

The example defines a <Snippet>Counter</Snippet> type with a <Snippet>sync.Mutex</Snippet> field. The <Snippet>Increment</Snippet> and <Snippet>Value</Snippet> methods call <Snippet>Lock</Snippet> and <Snippet>Unlock</Snippet> to protect the <Snippet>value</Snippet> field from concurrent access.

### RWMutex

The <Snippet>sync.RWMutex</Snippet> type is a reader/writer mutual exclusion lock that protects shared resources from concurrent access. Use it when multiple goroutines need to read a resource at the same time, but only one goroutine should write to it.

Here&apos;s an example of how to use <Snippet>sync.RWMutex</Snippet>:

```go

package main

import (
    "fmt"
    "sync"
)

type Cache struct {
    mu sync.RWMutex
    data map[string]string
}

func (c *Cache) Get(key string) string {
    c.mu.RLock()
    defer c.mu.RUnlock()
    return c.data[key]
}

func (c *Cache) Set(key, value string) {
    c.mu.Lock()
    defer c.mu.Unlock()
    c.data[key] = value
}

func main() {
    cache := Cache{data: make(map[string]string)}

    cache.Set("foo", "bar")
    fmt.Println("Value of foo:", cache.Get("foo"))
}
```

The example defines a <Snippet>Cache</Snippet> type with a <Snippet>sync.RWMutex</Snippet> field. The <Snippet>Get</Snippet> method calls <Snippet>RLock</Snippet> and <Snippet>RUnlock</Snippet> to protect the <Snippet>data</Snippet> field during concurrent reads. The <Snippet>Set</Snippet> method calls <Snippet>Lock</Snippet> and <Snippet>Unlock</Snippet> to protect it during concurrent writes.

## Error handling techniques

### Error groups

The <Snippet>errgroup</Snippet> package in the <Snippet>golang.org/x/sync</Snippet> module handles errors from a group of goroutines. It runs a collection of goroutines and returns the first error encountered.

Here&apos;s an example of how to use <Snippet>errgroup</Snippet>:

```go

package main

import (
    "fmt"
    "golang.org/x/sync/errgroup"
)

func main() {
    g := new(errgroup.Group)

    for i := 0; i < 5; i++ {
        i := i
        g.Go(func() error {
            if i == 3 {
                return fmt.Errorf("goroutine %d failed", i)
            }
            fmt.Println("Hello from goroutine", i)
            return nil
        })
    }

    if err := g.Wait(); err != nil {
        fmt.Println("Error:", err)
    }
}
```

The example creates an <Snippet>errgroup.Group</Snippet> and calls its <Snippet>Go</Snippet> method for each goroutine it wants to run. Then it calls <Snippet>Wait</Snippet> to block until all the goroutines have finished, and checks whether there was an error.

### Error channels

Channels can carry errors from goroutines back to the main function, so you handle them in one place instead of in each goroutine.

Here&apos;s an example of how to use error channels:

```go

package main

import (
    "fmt"
)

func worker(ch chan<- error) {
    if err := doWork(); err != nil {
        ch <- err
        return
    }
    ch <- nil
}

func doWork() error {
    // ...
    return nil
}

func main() {
    ch := make(chan error, 1)

    go worker(ch)

    if err := <-ch; err != nil {
        fmt.Println("Error:", err)
    }
}
```

The example defines a <Snippet>worker</Snippet> function that takes an error channel as an argument. If the work fails, it sends the error to the channel. The main function creates an error channel and starts the worker goroutine. The receive from the channel blocks until the worker sends its result, and main handles the error if there is one.

## Common design patterns

### Fan-in

The fan-in pattern combines the output of multiple goroutines into a single channel. Use it to process data from multiple sources concurrently.

Here&apos;s an example of how to use the fan-in pattern:

```go

package main

import (
    "fmt"
    "sync"
)

func producer(id int, out chan<- string) {
    for i := 0; i < 3; i++ {
        out <- fmt.Sprintf("producer %d: value %d", id, i)
    }
}

func main() {
    out := make(chan string)
    var wg sync.WaitGroup

    for id := 1; id <= 2; id++ {
        wg.Add(1)
        go func(id int) {
            defer wg.Done()
            producer(id, out)
        }(id)
    }

    // Close the merged channel once every producer has finished
    go func() {
        wg.Wait()
        close(out)
    }()

    for v := range out {
        fmt.Println("Received:", v)
    }
}
```

The example starts two <Snippet>producer</Snippet> goroutines that send values to the same channel. Neither producer can close that channel, because the other may still be sending. A <Snippet>sync.WaitGroup</Snippet> tracks both, and a separate goroutine closes the channel after they finish. The main function ranges over the merged channel, so it receives every value and returns once the channel closes.

### Fan-out

The fan-out pattern distributes the work of a single goroutine to multiple worker goroutines. Use it to process a large amount of data concurrently.

Here&apos;s an example of how to use the fan-out pattern:

```go

package main

import (
    "fmt"
    "sync"
)

func worker(id int, in <-chan int, out chan<- int) {
    for v := range in {
        out <- v * 2
    }
}

func main() {
    in := make(chan int)
    out := make(chan int)
    var wg sync.WaitGroup

    for i := 0; i < 5; i++ {
        wg.Add(1)
        go func(id int) {
            defer wg.Done()
            worker(id, in, out)
        }(i)
    }

    go func() {
        for i := 0; i < 5; i++ {
            in <- i
        }
        close(in)
    }()

    // Close out only after every worker has stopped sending
    go func() {
        wg.Wait()
        close(out)
    }()

    for v := range out {
        fmt.Println("Received value:", v)
    }
}
```

The example defines a <Snippet>worker</Snippet> function that receives values from an input channel, processes them, and sends the results to an output channel. The main function starts five workers that read from the same input channel. Several workers write to the output channel, so none of them can close it without risking a panic when another worker sends. A <Snippet>sync.WaitGroup</Snippet> tracks the workers, and a separate goroutine closes the output channel after all of them finish. The main function ranges over the output channel until it closes.

### Pipeline

The pipeline pattern connects multiple stages of processing using channels. Use it to process data in a series of steps.

Here&apos;s an example of how to use the pipeline pattern:

```go

package main

import (
    "fmt"
)

func producer(out chan<- int) {
    for i := 0; i < 5; i++ {
        out <- i
    }
    close(out)
}

func doubler(in <-chan int, out chan<- int) {
    for v := range in {
        out <- v * 2
    }
    close(out)
}

func consumer(in <-chan int) {
    for v := range in {
        fmt.Println("Received value:", v)
    }
}

func main() {
    out := make(chan int)
    out2 := make(chan int)

    go producer(out)
    go doubler(out, out2)

    // consumer runs on the main goroutine, so main returns
    // only after the last value has gone through the pipeline
    consumer(out2)
}
```

The example defines three functions. <Snippet>producer</Snippet> sends values to an output channel. <Snippet>doubler</Snippet> receives values from an input channel, processes them, and sends the results to an output channel. <Snippet>consumer</Snippet> receives values from an input channel. The main function starts the producer and doubler as goroutines and runs the consumer itself. Each stage closes its output channel when its input runs out, so the consumer&apos;s range loop ends after the last value and the program exits.

## Conclusion

This post covered advanced synchronization tools, error handling techniques, and common design patterns for concurrent Go applications.

<Snippet>sync.WaitGroup</Snippet> waits for a collection of goroutines to complete. <Snippet>sync.Mutex</Snippet> protects shared resources from concurrent access. <Snippet>sync.RWMutex</Snippet> lets multiple goroutines read a resource at the same time, but only one write to it.

The <Snippet>errgroup</Snippet> package handles errors from a group of goroutines, and error channels propagate errors from goroutines to the main function.

Fan-in, fan-out, and pipeline are common design patterns for writing concurrent Go programs.
