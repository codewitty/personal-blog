In my previous post, [Error handling fundamentals in Go](/blog/go-errors), I compared Go's error handling with other popular languages. This post covers best practices for robust Go code.

Go's error handling is simple, and it lets you handle errors efficiently without hurting readability.

## 1. Use the errors package for simple errors

For a plain error message, use the <Snippet>errors</Snippet> package:

```go
import "errors" 

func divide(x, y int) (int, error) {
    if y == 0 {
        return 0, errors.New("cannot divide by zero")
    }
    return x / y, nil
}
```

## 2. Custom error types for better context

In more complex cases, a custom error type gives you more context and lets callers tell errors apart:

```go
type MyError struct {
    Msg string
}

func (e *MyError) Error() string {
    return e.Msg
}

func someFunc() error {
    if err := someOtherFunc(); err != nil {
        return &MyError{Msg: "An error occurred in someFunc"}
    }
    return nil
}
```

## 3. Use the fmt.Errorf function for formatted errors

fmt.Errorf creates formatted error messages:

```go
func divide(x, y int) (int, error) {
    if y == 0 {
        return 0, fmt.Errorf("cannot divide %d by zero", x)
    }
    return x / y, nil
}
```

## Conclusion

With the errors package, custom error types, and fmt.Errorf, you can handle errors cleanly in many situations.
